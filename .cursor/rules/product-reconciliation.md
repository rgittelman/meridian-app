# Product reconciliation — Meridian

We are **not** restarting Meridian. This phase **unifies and strengthens** UX architecture and emotional experience while preserving what already works.

## Non-negotiables

- **Do not** redesign from scratch or discard existing work blindly.
- **Do** audit, group overlaps, remove redundancy, simplify mental models, and align visuals + interactions.
- **Preserve**: valuable workflows, technical investments, data shapes where possible, brand equity.
- **Improve**: navigation coherence, emotional consistency, hierarchy, AI prioritization, capture speed, focus clarity.

## North star

Meridian evolves toward an **intelligent, calm, predictive, low-friction, emotionally reassuring** personal OS for busy adults.

The user should **not** wonder:

- “Where does this go?”
- “What should I do first?”

## UX goal (explicit)

Not “more features.” **Reduce mental load** while **increasing trust and momentum.**

## Evaluation gate (every screen / feature)

Ask:

> **Does this reduce or increase cognitive burden?**

If it **increases** burden without **massive** value → **remove, defer, or simplify**.

## Reconciliation playbook (when changing the product)

1. **Audit** existing features and flows (what exists, who it’s for, how often used).
2. **Group** overlapping concepts (same job, different surface).
3. **Flag** cognitive overload (too many choices, unclear hierarchy, duplicate entry points).
4. **Consolidate** redundant navigation and actions (one obvious path per job).
5. **Simplify** mental models (fewer “modes,” consistent naming).
6. **Unify** visual language and interaction patterns (tokens, motion, affordances).
